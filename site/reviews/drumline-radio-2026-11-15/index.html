01Critical

Accessible names don't match the visible text

index.html:24, src/ui/dial.ts:37

The readout is named "Song details" while it shows the song title, so a voice-control user saying "click Für Elise" hits nothing. Station buttons are named "<title>, station <n>", which doesn't match their visible "CLASSICS · SYNTHWAVE 88.1 Für Elise".

FixBegin the readout's name with the visible text (e.g. aria-label="Für Elise, song details", updated with the title) or drop aria-label and use aria-describedby. For stations, start the name with the visible frequency and title: "88.1 Für Elise".

03Critical

Now-playing display collapses at tablet width

src/ui/style.css:472 (.readout flex: 1; min-width: 0)

At 768px the brand, view tabs, info button and meters leave the readout about 75px wide, so the title and status are cut off ("Für", "Press p"). There is no breakpoint between 640px and desktop.

FixUse the stacked header layout from the 640px media query up to about 960px, or give .readout a min-width (e.g. 220px) and let the header wrap.

Dropped as false positives (5)
  • dark-glow ×2 (impeccable): The neon pink glow is the chosen Synthwave style (the site has a style switcher), not a default.
  • codex-grid-background (impeccable): This is the tuner dial's tick-mark scale (style.css:747), which does a job on the dial.
  • repeating-stripes-gradient (impeccable): The same dial tick marks.
  • nested-cards (impeccable): The only nesting in the screenshots is inset display screens (readout, dial) inside panels, which is hardware, not card-in-card.

What works well

  • No horizontal overflow at 390, 768 or 1280, and no console errors on load.
  • Thorough accessibility basics: labelled radiogroups for views, categories and styles, aria-pressed on toggles, labelled dialogs, aria-live on the title, and two prefers-reduced-motion blocks.
  • Real phone layout work, not just shrinking: full-width view tabs, a stacked readout, and bigger transport buttons.

Not checked

  • Only the default Synthwave style and the idle Radio view were rendered; Jukebox, Playlist, dialogs, the playing state and the other styles were not.
  • Keyboard walk-through and screen-reader testing (manual).
  • The instruments lab page was scanned as source only, not rendered.
  • Rendered impeccable findings come without selectors; their source lines are mapped by hand, so treat them as approximate.
